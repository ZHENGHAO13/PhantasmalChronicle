# Phantasm Maker

`Phantasm Maker` 是面向 `PhantasmBriefing` 内容工作流的本地网页作者器。

编辑器有意保持为单个 `index.html`，便于直接双击离线使用，不依赖本地开发服务器或外部 CDN。

第一次使用请先阅读：[中文快速教程](../../QUICK_START.zh-CN.md) · [English Quick Start](../../QUICK_START.en-US.md)。本文后续内容作为编辑器功能参考。

当前版本已经覆盖以下核心内容层：

- `phantasm_quests`
- `phantasm_dialogues`
- `phantasm_npc_bindings`
- `phantasm_wallet`
- `phantasm_shops`
- `phantasm_trades`

它的目标不是做一个脱离项目实际运行时的数据沙盒，而是作为 `PhantasmBriefing` 当前正式内容结构的可视化作者工作台。

## 当前能力

当前作者器已支持：

- 默认开启“新手模式”，隐藏内部 ID、坐标、排序值和 JSON 等技术参数
- 首页三步引导与下一步提示，不再启动时自动载入演示内容
- 一键创建“任务 + 对话 + NPC”完整委托链路
- NPC、村民职业、结构、维度和常用物品的可搜索候选项
- 一键修复常见 ID、命名空间、引用、钱包计价和交易数量问题
- 任务基础字段编辑
- 任务树父任务 / 推荐后续任务配置
- 任务树节点坐标预览与拖拽写回
- 对话节点与选项编辑
- 实体绑定到对话入口
- 为 NPC 选择对应任务并自定义“前置未完成”对白；PB 与 FTB 前置均自动判定
- 为 NPC 配置结构生成规则、实体模型、村民职业、生成锚点与偏移
- 钱包配置
- 商店分类与报价配置
- 独立交易分类与条目配置
- `Trade` 与任务、对话、NPC、商店、钱包同级显示在主导航中
- 导入已有 `briefing_pack`
- 导出并校验 `briefing_pack`
- 写入完成后自动通知正在运行的游戏热加载任务与关联内容，无需重启或手动执行 `/reload`

## 打开方式

1. 用新版 `Edge` 或 `Chrome` 打开 `index.html`
2. 点击“选择整合包”，选择同时包含 `config` 和 `mods` 的整合包根目录
3. 编辑器会自动读取已有 `briefing_pack` 和 FTB Quests 任务；没有旧内容时可从空白开始
4. 第一次制作推荐点击“新建任务 + 对话 + NPC”，再按页面提示填写名称、对白与出现地点
5. 点击“检查并写入”，有常见格式问题时可先使用“一键修复常见格式”

点击“写入并热加载”后，编辑器会先完成全部文件写入，再直接向同一台电脑上正在运行的游戏发送一次热加载请求。PhantasmBriefing 平时不会轮询文件，也不会定时重载；只有点击保存才会执行。请求成功后，游戏会重新读取任务、对话、NPC 绑定、钱包、商店和交易，并刷新在线玩家的任务追踪，服务器管理员会在聊天栏收到完成提示。若游戏未运行或尚未进入世界，文件仍会正常保存，编辑器会明确提示本次未能热加载。

右侧“新手模式”默认开启。关闭后才会显示命名空间、内部 ID、生成偏移、排序值和 JSON 条件等高级字段。

如果浏览器不支持目录写入，也可以只把它当作本地 JSON 预览器使用，再手动复制导出结果。

## 输出目录

默认直接写入：

```text
config/phantasmbriefing/briefing_pack/
```

生成的子目录为：

```text
phantasm_quests/
phantasm_dialogues/
phantasm_npc_bindings/
phantasm_wallet/
phantasm_shops/
phantasm_trades/
```

## 各视图说明

### 项目

- 选择整合包项目根目录
- 读取已有 `briefing_pack`
- 查看当前任务、对话、绑定、钱包、商店、交易总数

### 任务

- 编辑 `questId`、标题、描述、追踪标题、初始阶段、前置任务
- 前置任务可选择本模组任务，也可直接填写 FTB Quests 内部任务 ID
- 可填写 `ftbQuestId`，在本模组任务完成时同步完成关联的 FTB 任务
- 可视化维护 `phases` 与阶段间的 `nextPhaseId` 流转
- 编辑阶段目标 `objectives`，支持 `manual / visit / talk_to / collect / kill`
- 编辑任务接取/完成动作、阶段进入动作和目标完成动作
- 逐条新增和编辑任务解锁条件、目标可见条件
- 编辑 `parentQuestIds` 与 `nextQuestIds`
- 编辑 `treeLayout.treeId / x / y`
- 在任务树预览中直接拖拽节点，写回布局坐标

任务树预览主要用于作者布局，不是运行时界面的 1:1 复刻。

FTB 前置说明：将 FTB Quests 的内部任务 ID（例如 `1B766784FBBE7D51`）填入“外部 FTB 前置任务 ID”。它与“本模组前置任务”互斥，并共用运行时的 `requiredQuestId`。外部 FTB 前置只参与解锁判断，不会显示为本地任务树节点。

选择整合包项目文件夹时，编辑器会只读扫描以下常见目录：

```text
config/ftbquests/quests/
defaultconfigs/ftbquests/quests/
```

编辑器会递归读取 `.snbt` 和 `.json`，提取 FTB 任务的内部 ID 与标题，并在“外部 FTB 前置任务”输入框中提供可搜索候选项。无法识别的文件会被跳过；仍可手动粘贴任务 ID。

### 对话

对话选项当前只保留 3 类行为：

- `关闭对话`
- `承接任务并继续对话`
- `只跳转到下一节点`

其中“触发对话”本身由实体绑定页完成，不在对话动作中重复暴露。

### 实体绑定

实体绑定页填写的是 `dialogueId`，导出时会自动转换成运行时需要的起始节点：

```text
dialogueId::startNodeId
```

这样在游戏内对准实体并按“开始与 NPC 对话”键时，会直接进入该对话容器的开场节点。默认按键为 `V`，可在 Minecraft 按键设置中修改。

实体绑定页还可选择“此 NPC 对应的任务”。若该任务配置了本模组前置任务或外部 FTB 前置任务，玩家尚未完成任一前置时，NPC 只播放可自定义的“前置未完成时的提示”，不会打开正式对话或记录本次对话交互；前置完成后无需改配置，NPC 会自动恢复原对话。

实体绑定还可以添加一条或多条“结构生成规则”。每条规则可配置目标结构、维度、结构锚点、坐标偏移、朝向、AI、名称显示和村民初始等级。“自动贴合安全地表”默认开启，会避免 NPC 落到结构包围盒的地下部分、墙内、液体或普通建筑屋顶；要塞、地下城等确实需要生成在内部的规则可关闭该选项。导出后的 NPC 会在每个匹配结构实例中只生成一次；同一绑定 ID 的多个 NPC 实例读取同一玩家的任务、旗标和对话条件进度。

### 钱包

钱包页用于配置货币语义，而不是玩家独立数值账户。

新手模式下只需填写钱包名称、货币名称、显示图标和可支付物品。安装 `Lightman's Currency` 后，游戏运行时会自动识别玩家模组钱包中与 `itemIds` 对应的货币，无需在编辑器中额外开启兼容选项。

当前可编辑字段包括：

- `walletId`
- `title`
- `currencyName`
- `iconItemId`
- `itemIds`
- `sortOrder`

### 商店

首页的“钱包商店模板”会同时创建钱包与商店，并生成只使用 `walletCost` 的有效报价；模板不会再混入普通物品商店使用的 `costA / costB`，创建后可直接校验和导出。

商店分为两种互斥支付模式：

- 绑定钱包：报价填写 `walletCost`，不填写 `costA / costB`
- 不绑定钱包：报价至少填写 `costA`，不使用 `walletCost`

编辑器现在会在切换支付方式时自动调整报价：绑定钱包会清空物品成本并补上有效钱包价格；取消绑定则会恢复一个可直接修改的物品成本，避免新手创建出互相冲突的配置。

商店页用于配置：

- `shopId`
- `title`
- `walletId`
- `openCondition`
- 分类列表
- 报价列表

规则说明：

- 填写了 `walletId` 时，该商店会被视为钱包商店
- 钱包商店应使用 `walletCost` 计价，不应再填写 `costA / costB`
- 未填写 `walletId` 时，该商店会被视为普通物品商店
- 普通物品商店至少需要 `costA`

### Trade（交易）

`Trade` 是正式主导航模块，用于编辑独立的 `phantasm_trades` 数据层。

交易页用于配置：

- `tradeId`
- `title`
- `description`
- `openCondition`
- 分类列表
- 交易条目列表

每个交易条目当前遵循运行时约束：

- `costs` 需要 1 到 2 个物品
- `rewards` 必须且只能有 1 个物品

## 导入与导出

作者器会尝试按当前运行时代码兼容以下情况：

- 新字段名
- 旧样例中的部分别名字段
- `entries` 既可能是对象，也可能是数组

导出时会优先按当前项目运行时需要的字段结构生成 JSON。

## 校验范围

导出页“检查数据”当前会覆盖以下问题：

- 任务前置与推荐后续任务引用是否存在
- 对话起始节点与跳转节点是否存在
- 对话承接任务选项是否引用有效任务
- 实体绑定是否引用有效对话
- 实体绑定所选的对应任务是否存在
- 商店是否引用有效钱包、分类、任务
- 钱包商店和普通物品商店的成本字段是否冲突
- 交易分类、任务引用、成本数量、奖励数量是否符合约束

“一键修复常见格式”会在写入前处理可确定的安全修复，例如补全命名空间、生成缺失 ID、修复因 ID 变化产生的引用、规范物品/实体/结构 ID，以及补齐钱包商店和交易条目的必需默认值。修复后仍会再次执行完整校验。

## 当前边界

当前版本已经从早期的轻量任务编辑页扩展成完整作者工作台，但依然保持以下边界：

- 优先覆盖项目当前稳定运行的字段
- 优先保证导出 JSON 与运行时一致
- 更复杂的扩展条件仍建议在导出后手动微调
- 任务树拖拽当前只负责写回节点坐标，不实时重算整张预览连线布局

## 建议工作流

推荐按这个顺序制作内容：

1. 先建任务
2. 再建对话并把选项接到任务
3. 再建实体绑定，把实体挂到对话入口
4. 如需终端经济内容，再建钱包
5. 在钱包基础上建商店，或直接建独立交易
6. 最后去导出页统一检查和写入
